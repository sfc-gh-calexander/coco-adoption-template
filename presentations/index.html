Get CoCo running on your Snowflake account

CoCo is Snowflake's AI coding agent. It reads your data, writes and runs code against it, and builds things - all inside your Snowflake governance boundary. This guide covers exactly one thing: getting CoCo installed and connected. What you build with it after that is up to you.

Three ways to run CoCo

Pick whichever fits how you work. You are not locked into one - many people start in Snowsight and add Desktop or CLI later.

Already have a Snowflake account? Start here instead

No install required

CoCo is built into Snowsight. Sign in to Snowsight and click the blue star icon in the bottom-right corner to open the CoCo panel. That's it - you're using CoCo, immediately, with no download and no local setup. This is the fastest way to try it before installing Desktop or the CLI.

Not sure what to try first?

Ask CoCo in plain English. A few starting points people find useful on their own accounts:

  • "What tables have I not touched in the last 90 days?"
  • "Which warehouses cost me the most this month, and why?"
  • "Which of my tables look like they hold sensitive data based on column names, and do any of them have a masking policy attached?"
  • "Summarize what changed in <table_name> over the last 30 days."
  • "Write a stored procedure that dedupes rows in <table_name>."

CoCo shows you the SQL it runs along the way, so you can check its reasoning against your own account instead of taking it on faith.

Before you start

Whichever surface you pick, your Snowflake role needs one of these database roles:

RoleWhat it's forGranted by default?
SNOWFLAKE.CORTEX_USERCore CoCo access - chat, read schema and data, write and run codeYes, via PUBLIC on most accounts
SNOWFLAKE.CORTEX_AGENT_USERBuilding and running Cortex Agents specificallyNo - an admin grants this explicitly

Most users already have SNOWFLAKE.CORTEX_USER without any admin action. If CoCo says you don't have access, ask your Snowflake admin to check the grant.

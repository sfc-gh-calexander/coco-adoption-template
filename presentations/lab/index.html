Hands-On Lab: Account-Specific CoCo Build

Six phases from a blank slate to a deployed, evaluated AI agent that answers a question using the customer's own Snowflake data. Follow the tabs in order.

1 · Setup→ 2 · Semantic View→ 3 · Agent→ 4 · Evaluate→ 5 · Demo→ 6 · Handoff
The contract: each phase states its entry condition and its exit artifact. Confirm the gate at the end of a phase before advancing - never move on with a failing gate.

New here? Start with Setup and work through the tabs in order.

Step 1 of 5

Setup

From cold start to build-ready in 30 minutes.

Entry Condition

You have a customer meeting scheduled and access to their Snowflake account (or a trial account). You do not need to have built anything yet.

Before the session: three discovery questions

Run these questions before touching Snowflake. Your answers determine what you build.

  1. What decision does your team make every week that takes longer than it should?
  2. Where does the data that informs that decision live today?
  3. If you could ask that data a question in plain English and get an answer in 10 seconds, what would you ask?

Map question 3 to a table. That table is your build target. Write the one-sentence build brief:

Build an agent that answers [question from step 3] using [table from step 2].
What CoCo can build: the build brief above assumes a conversational agent (semantic view + Cortex Analyst agent) - that is the pattern Tabs 2 and 3 walk through as a worked example. CoCo is a general coding agent, so the same three discovery questions can just as easily point to a Streamlit app or dashboard, a dbt model or Dynamic Table pipeline, or a notebook analysis. Swap in whichever artifact actually answers the customer's question.

Prerequisites checklist

  • Snowflake account with Cortex features enabled
  • CoCo enabled on the account - verify in Snowsight under Projects › CoCo
  • Role with CREATE SEMANTIC VIEW and CREATE AGENT privileges (SYSADMIN or equivalent)
  • 1–2 source tables identified that answer the business question
  • One-sentence build brief written (above)
  • A warehouse available (XS is fine)

Verify your setup

Run these in Snowsight or CoCo before building:

-- Verify target tables are accessible
SHOW TABLES IN DATABASE <customer_db>;

-- Check row count and data freshness
SELECT COUNT(*), MAX(<date_column>) 
FROM <customer_db>.<schema>.<table>;

-- Verify CREATE SEMANTIC VIEW privilege
SHOW GRANTS TO ROLE <your_role>;
Gate - do not advance until

Target tables are accessible, have recent data, and you have confirmed CREATE SEMANTIC VIEW and CREATE AGENT privileges.

Exit artifact: the one-sentence build brief is filled in and the tables are confirmed accessible.

Step 2 of 5 · Agent pattern, part 1 of 2

Semantic View

Where accuracy is won or lost.

Entry Condition

Target tables confirmed, build brief written, privileges verified.

Reference: for a full semantic view skeleton, see starter/semantic_view_example.sql in the repo. Copy it and adapt to the customer's tables.

Step-by-step

Follow this order exactly. Clause order is enforced by Snowflake.

1. Define TABLES

CREATE OR REPLACE SEMANTIC VIEW <db>.<schema>.sv_<account_name>
TABLES (
  main_table PRIMARY KEY (id)
    COMMENT 'Describe the table and its grain here.'
    AS SELECT * FROM <db>.<schema>.<table>
)

2. Add DIMENSIONS

Use business names, not column names. Add synonyms for how users actually ask.

DIMENSIONS (
  main_table.status
    SYNONYMS ('state', 'current status')
    COMMENT 'Current status of the record.',
  main_table.category
    SAMPLE_VALUES ('active', 'pending', 'closed')
    IS_ENUM = TRUE
    COMMENT 'Category type.',
  main_table.created_date
    COMMENT 'Date the record was created.'
)

3. Add METRICS

At least one metric for the KPI the build brief is about.

METRICS (
  total_count AS COUNT(main_table.id)
    SYNONYMS ('count', 'number of records', 'total')
    COMMENT 'Total number of records.'
)

4. Add AI clauses (in this order)

COMMENT = 'Describe what this covers and the data grain.'

AI_SQL_GENERATION INSTRUCTIONS
$$
  Default to the current fiscal year unless the user specifies otherwise.
  Round dollar amounts to two decimal places.
$$

AI_QUESTION_CATEGORIZATION INSTRUCTIONS
$$
  If a question is not answerable from this data, say so clearly.
$$

AI_VERIFIED_QUERIES (
  VERIFIED_QUERY 'primary question'
    QUESTION 'Phrase it exactly as the customer would ask'
    SQL 'SELECT ... FROM ...'
    VERIFIED = TRUE
);
Gate - do not advance until

The semantic view deploys without error and a test query returns an accurate answer to the build brief question.

Exit artifact: a deployed semantic view that answers the build brief question correctly.

Step 3 of 5 · Agent pattern, part 2 of 2

Agent

Wire the semantic view to a conversational interface.

Entry Condition

Semantic view is deployed and validated against the build brief question.

Note: a data governance skill (providing pre-built patterns for regulated industries) will be added here when available. For now, use the generic agent spec below and adapt to your vertical.

Create the agent

In CoCo or Snowsight, run:

CREATE OR REPLACE AGENT <account_name>_analyst
  TOOLS = (
    TOOL_TYPE   => CORTEX_ANALYST_TEXT_TO_SQL,
    TOOL_NAME   => 'data_analyst',
    SEMANTIC_VIEW => '<db>.<schema>.sv_<account_name>',
    TOOL_DESCRIPTION => 'Answers questions about <what this SV covers>. 
      Use for: questions about <specific domain>. 
      Do not use for: questions outside <domain>.'
  )
  INSTRUCTIONS = (
    ORCHESTRATION => 'You answer questions about <customer domain>. 
      Use the data_analyst tool for all data questions. 
      If you cannot answer from the available data, say so.',
    RESPONSE => 'Answer in plain language. Lead with the number or direct answer. 
      Explain briefly. Keep responses under 3 sentences unless asked for detail.'
  );

Test with three questions

Open the agent in CoCo and run all three:

  1. The exact question from the build brief - this must work
  2. A follow-up the customer is likely to ask (a refinement or drill-down)
  3. An out-of-scope question - verify the agent says it cannot answer, not that it hallucinates
Gate - do not advance until

All three test questions return useful, accurate answers (or a clear "I cannot answer that" for the out-of-scope question).

Exit artifact: deployed agent that answers the build brief question accurately in the customer's Snowflake environment.

Step 4 of 6

Evaluate

Score the agent against a ground-truth question set instead of eyeballing three test questions.

Entry Condition

Agent is deployed and validated against the three test questions from the Agent tab.

Why this matters: manual spot-checks catch obvious misses but do not scale and are not repeatable across iterations. Snowflake's Cortex Agent Evaluations run the agent against a ground-truth set and score the answers, giving you a real number instead of a feel.

Set up the evaluation

  1. Copy starter/eval_ground_truth_example.csv and starter/eval_config_example.yml into the session
  2. Replace the example rows in the ground truth CSV with 5-10 real questions and correct answers for this customer's data - include a couple of edge cases and out-of-scope questions, not just the easy ones
  3. Load the CSV into a table the eval dataset will point at
  4. Update eval_config_example.yml: set agent_name to the deployed agent, table_name to the table you just loaded, and remove the dataset block after the first successful run

Run the evaluation

CALL EXECUTE_AI_EVALUATION(
  'START',
  OBJECT_CONSTRUCT('run_name', '<customer>_baseline'),
  '@<database>.<schema>.eval_config_stage/eval_config_example.yml'
);
Gate - do not advance until

The evaluation run completes without error, and answer_correctness / logical_consistency scores are reviewed for every question - not just the average. If a question consistently scores low, fix the semantic view or agent spec and re-run rather than demoing around it.

Exit artifact: an evaluation run with reviewed scores for every ground-truth question.

Step 5 of 6

Demo

Running the session and handling objections.

Entry Condition

Agent is deployed and validated. All three test questions return accurate answers.

Demo script

  1. Open CoCo and navigate to the agent
  2. Ask the build brief question - let the customer see their own data answer it in 10 seconds
  3. Ask the follow-up question you prepared - show that the agent handles context
  4. Invite the customer to ask a question they care about - do not script this
  5. Show the generated SQL for one answer - this addresses the "black box" objection before it is raised

Objection handling

ObjectionResponse
"We already have Copilot / ChatGPT" Those tools answer from the internet. This answers from your Snowflake data, with your governance controls, and it does not leave your environment. The generated SQL is auditable by your data team.
"My data team won't trust it" Show them the SQL. Every answer is a SQL query against your tables. They can validate the query, add it to a verified query set, and the model will always use it for that question going forward.
"This is just a demo, not production" The semantic view and agent you just saw are already production objects in your Snowflake account. There is no sandbox to promote out of. This is the production deployment.
"What does this cost to run?" Cortex AI usage is billed per token. For a typical analyst question at this data volume, the cost is in the range of cents per query. Your current warehouse handles the SQL execution at standard rates.
"How do we maintain this?" The semantic view is SQL in your source control. The agent spec is a DDL statement. You update them the same way you update any other database object - SQL, version control, CI/CD if you want it.
Exit condition

The customer has asked at least one unscripted question and the agent answered it accurately. The AE can describe what the demo answered in one sentence.

What to do with the deployed agent

  • Leave the semantic view and agent deployed in the customer's Snowflake account - this is their artifact
  • Grant access to the relevant roles so the customer's team can use it
  • Send the customer the agent name and instructions for accessing it in CoCo or Snowflake Intelligence
  • Log the use case in SFDC before the day ends
Done when

The handoff card is filled in, the AE has a copy, and the use case is logged in SFDC.
